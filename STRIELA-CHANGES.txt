ChemDraft - changes on the striela-changes branch
=================================================

Fork: https://github.com/romualdasstriela/ChemDraft (branch striela-changes)
Based on: https://github.com/jgassens/ChemDraft (main)
Every push to this branch builds a "ChemDraft (dev)" Windows installer in GitHub Actions
(workflow "Windows dev build", artifact chemdraft-dev-windows-installer).


1. Vertical toolbars
   - Each toolbar can be laid out horizontally or vertically: View > Customize Toolbars,
     Horizontal/Vertical choice on each toolbar's row.
   - View > Arrange Toolbars stacks the toolbar windows top to bottom down the side,
     starting below the docked Main toolbar.
   - The Main toolbar is no longer a floating window: it is docked as a fixed strip across
     the top of the document window, right under the File menu row. Its pop-out menus open
     downward. View > Toolbars still shows or hides it. All other toolbars still float.
     It is always horizontal: Customize Toolbars no longer offers Vertical for it, and an
     earlier saved Vertical choice is ignored.
   - When the window is narrower than the Main toolbar, its sections (split at the divider
     lines) wrap onto a second row instead of the right end being cut off.

2. Relabelling atoms by hovering and typing
   - Fixed: after relabelling one hovered carbon with a key, pressing a key over the next
     atom typed letters next to the previous label instead of relabelling the new atom.
   - Shift+B gives Br (b stays B), Shift+C gives Cl (c stays C), Shift+S gives Si (s stays S).
   - A letter that is not an element (A, D, E, G, J, L, M, Q, R, T, X, Z) also relabels the
     hovered atom, shown as the capital letter (x gives X). Over an atom these letters no
     longer act as tool shortcuts (e over an atom gives E, not the Eraser); with nothing
     hovered they still do. Any letter over another atom starts a new label there, so a
     multi-letter label like OMe is typed with the pointer kept on its atom (a drift onto a
     bond or empty page is fine). The k (carbonyl) key over an atom is unchanged.
   - G, J, L and Z now count as placeholder labels like X and R, so no letter label shows
     the "?" unknown-label badge.
   - Bare letters X, A, Q, M, L and R are no longer drawn with the purple "?" query-atom
     mark, and neither are numbered R-groups (R1, R2, r1, R₁, R¹). It stays only for
     explicit query notation: *, R# and bracketed atom lists.

3. Periodic Table toolbar
   - New toolbar with the full periodic table. Click an element, then click atoms to set
     them to that element.

4. Bond tools
   - The Single Bond button in the Structure toolbar has a pop-out with Single, Double and
     Triple Bond. The button shows whichever bond was picked last.
   - Clicking a single bond with the bond tool makes a centred double bond (then triple).
   - In a ring, a double bond goes on the inner side of the ring automatically.
   - Triple bonds are linear: a triple bond added to a single bond, and the next bond
     grown from a triple bond, continue at 180 degrees.
     Known gap: clicking an existing angled bond with the Triple tool makes it triple
     but does not straighten it.

5. Copy to Word with Ctrl+C
   - Ctrl+C (and Cut, Edit > Copy) also puts a JPG picture of the copied objects on the
     clipboard (white background, 4x resolution, pastes at drawn size), so Ctrl+V in Word
     pastes the drawing. Copy As > PNG still exists.
   - Copy and paste inside ChemDraft is unchanged.
   - When a picture is on the clipboard, plain text is left off (Word would paste text
     instead of the picture), so text no longer pastes into Notepad from Ctrl+C.
   - The macOS side (public.jpeg) is written but untested.
   - Windows: Ctrl+C also puts a vector picture (Enhanced Metafile, CF_ENHMETAFILE) on the
     clipboard, so Word, PowerPoint and Excel paste sharp lines and real Arial text at the
     drawing's real size, with no white box behind it. The JPEG stays, as a plain bitmap
     (CF_DIBV5) for apps that take only bitmaps; its "JFIF" entry is left out when the vector
     picture is there, because Word's plain paste took the JPEG over it. The metafile is written from the exported SVG (export-engine svgToEmf); shadows,
     glows and clip paths are left out, gradients become one colour, transparency is blended
     against white, and the white outline behind labels is left out (bonds already stop short
     of labels). macOS keeps the JPEG only.
   - Windows: the copy is also an editable "ChemDraft Drawing" object. Ctrl+V in Word (or
     PowerPoint, Excel) pastes it as an object that shows the vector picture; double-clicking
     it opens the drawing in ChemDraft as "Drawing in <document name>.chemdraft" (a temporary
     copy), and saving it there (Ctrl+S) puts the edited drawing and its new picture back into
     the Office document. The object stores the ChemDraft file and its picture, so it shows and
     reopens without ChemDraft running; ChemDraft is started for the double-click if needed.
   - ChemDraft registers the object type for this user at every start (HKCU\Software\Classes,
     no admin rights); the dev build ("ChemDraft (dev) Drawing") and the stable app have
     separate types and never open each other's objects. Office for Mac cannot edit such
     objects.
   - Insert > Object > "ChemDraft (dev) Drawing" in Word starts a new drawing: ChemDraft opens
     an empty page (Word shows a blank 40 x 20 mm placeholder until the first Ctrl+S).
   - File > Close and Return to Office Document (enabled only for a drawing opened from an
     Office document) saves the drawing back if it changed and closes its tab.
   - The drawing opens as the whole page with the copied objects where they were drawn; Word
     shows it hatched while it is open in ChemDraft, and closing the ChemDraft tab ends the
     editing (the hatching goes). The pasted object has the drawing's size at 100% zoom and
     keeps it through edits: every picture states its size for the screen it is used on, as
     Word measures pictures both against the screen's physical resolution and at 96 dpi.
   - Each step of the round trip is logged to %TEMP%\ChemDraft Office drawings\ole-log.txt
     (C:\Users\<you>\AppData\Local\Temp\...); the temporary copies are kept in that folder.

6. ACS Document 1996 as the default drawing style
   - Every new structure (drawn, placed from a template, or pasted as SMILES or molfile)
     now starts in the ACS Document 1996 journal style: 0.6 pt lines, 2.0 pt bold bonds,
     double-bond spacing 18% of the bond length, 14.4 pt bonds at 120 degrees, Arial 10 pt
     labels. Existing drawings and opened files keep their own style.
   - The values are what ChemDraft's own .cds importer reads from "ACS Document 1996.cds";
     the .cds file itself is not part of the repository. Structures the AI assistant and
     the command-line tools build still use the original ChemDraft style.

7. Page zoom buttons
   - Zoom In and Zoom Out buttons at the right end of the Main toolbar. They, and Ctrl++ /
     Ctrl+-, step through 25%, 50%, ... 300% in 25% steps. A zoom off that grid (after a
     pinch or Ctrl+wheel) goes to the next 25% level; above 300% Zoom Out returns to 300%.
   - The page can now zoom out to 25% (was 50%).
   - The buttons zoom about the middle of the visible canvas by moving the scrollbars, like
     Ctrl+wheel zoom, so every part of the page stays reachable by scrolling. (The first
     version shifted the page, which left its top and left edges beyond the scrollbars; a
     saved shift like that is cleared when a document reopens or on the next zoom.) When
     the whole page fits on screen after zooming out, it is brought into view.

8. Nicknames from your own folder
   - Preferences > Nicknames: choose a folder of nickname files (one CDXML structure per
     file, named by its label, e.g. Ad.cdxml = "Ad", with connection points where the group
     attaches). ChemDraft reads the folder every time it starts; the files are not copied
     into ChemDraft or this repository (the project forbids bundling another program's
     nickname list, and this fork is public).
   - Every group read from the folder is recognised as an atom label: typed "Ad", "Boc",
     "Ala", "TBDPS"... counts in the formula, is checked for the right number of bonds, and
     is written out as real atoms in SMILES / molfile / exports. Built-in groups with the
     same name win. A label that is also an element symbol ("Am", "Np") means the group
     only on an atom with bonds.
   - Groups that join at two atoms (amino-acid and nucleotide residues, PEG and phenylene
     linkers) are supported: the label needs exactly one bond per site, and the bonds are
     joined in reading order - the leftmost neighbour (then the highest) to the first site,
     e.g. Ala's N, the next to the second, e.g. its C=O.
   - Nested nicknames inside a file (DMTr, MMTr, PMB...) are expanded. Files that are not one
     definite structure are skipped and listed in Preferences (in the test folder: Asx, Glx,
     Xaa - "either of" / "any" placeholders). 513 of 516 files load.
   - New Nicknames toolbar (View > Toolbars): a search box and a button per group (x2 marks
     two-site groups). Pick one, then click atoms to label them; Esc exits.
   - With a nickname picked, a click on empty page places the group's whole structure there
     as real, editable atoms (in the new-structure style, selected); each attachment site
     gets a hydrogen, so "Ad" places adamantane.
   - User templates (your own nicknames): draw the group, select it WITHOUT the atom it is
     bonded to (that bond marks where it attaches; or draw a * atom on that bond and select
     it too), press Define Nickname at the right end of the Main toolbar, type the
     abbreviation in the Nicknames toolbar and press OK. Templates are listed in the
     toolbar's "user templ." tab (x removes one), are saved on this computer, and work like
     every other nickname: typed as a label, picked from the toolbar, placed on empty page.
     A template with the same name as a folder nickname replaces it; built-in names (OMe,
     Ph...) are refused.
   - An attachment site is optional: a whole selected structure with no bond to the rest and
     no * mark is kept as drawn (same orientation, no attachment site). It is placed on
     empty page as drawn and can label an atom with no bonds.
   - Define Nickname reads abbreviation labels in the selection (OMe, Ph, Boc, NHAc, OH, your
     own nicknames...): they count as the atoms they stand for in the template's formula and
     wherever the template is used as a label, and the template remembers the drawing with
     its labels, so placing it on empty page draws OMe as OMe, not O-CH3. A label that is not
     an element or a known abbreviation, or one whose bonds do not fit it, is refused with
     the reason.
   - The Nicknames toolbar's text fields (search, abbreviation) can be typed into: the
     floating toolbar takes the keyboard only while a field is in use.

9. Polymer bracket ( )n
   - New Polymer Bracket Tool beside the Curly and Square Bracket tools (Main toolbar and
     the annotation tools): a click places a pair of parentheses with an "n" label at the
     lower right, as ONE object - it moves, copies and deletes as a whole.
   - Resize it with the transform handles: the parentheses stretch to the box, the label
     stays the same text size beside the closing one.
   - Double-click it (Select or Text tool) to change the label: type, Enter keeps it, Esc
     cancels; an empty label removes it.
   - Only the two parentheses and the label catch clicks, so atoms and bonds drawn inside
     the brackets stay clickable.
   - The bracket uses the "polymer" kind the document model already had (drawn as a square
     bracket before), so it saves in .chemdraft files. CDXML export still writes only a
     placeholder for it, as for every native bracket.

10. Narrow-head reaction arrow (the default)
   - New "Reaction Arrow (Narrow Head)": same head length as the standard reaction arrow,
     half its base width (16 px long, 8 px wide instead of 16 px).
   - It is the Arrows button's own tool (Main toolbar and the Arrows toolbar) and first in
     its drop-down; the standard "Reaction Arrow" is second in that menu. The E shortcut
     also gives the narrow-head arrow.
   - Resizing the head (inspector or handle) keeps it narrow. It exports to CDXML as a
     normal reaction arrow (CDXML gets a standard head; the .chemdraft payload keeps the
     narrow one).
   - A saved toolbar customisation that hid or moved the old Reaction Arrow button no longer
     applies to the arrows button (its id changed); set it again in Customize Toolbars.

11. Turning a fragment about its single bond (Shift: third rotate handle)
   - Select a part of a structure that hangs from the rest by ONE single bond (e.g. the
     phenyl-R ring of a 2-bromobiphenyl, without the Br ring) and hold Shift: besides the
     rotate and 3D-rotate handles above the selection, a third handle appears (a bond with a
     loop around it). Drag it and the fragment turns in 3D about that bond, seen from the
     front. The rest of the molecule and the bond itself stay put.
   - 180 degrees swings it over to the other side of the bond (R moves from beside Br to the
     far side); 90 degrees shows it edge-on, on the bond line. With Shift still held the turn
     goes in 15 degree steps; released, it is free and clicks onto each 15 degrees nearby.
   - Past 90 degrees the fragment's wedges become hashes (and hashes wedges) and its
     off-centre double bonds change side, so its stereochemistry is kept.
   - The ordinary rotate handle is unchanged. A selection that meets the rest through more
     than one bond, or through a double bond, gets no third handle.
   - Which bond: the smallest piece hanging off a single bond that is in no ring and holds the
     whole selection. So selecting the ring alone, the ring with R, one atom of that ring, or a
     box round it that also clips the bonds to the other ring all turn that ring WITH its R
     about the biaryl bond. (The first version needed the selection to meet the rest through
     exactly one bond, so a box that clipped the biaryl or the Br bond showed only two handles.)
   - Drag the handle sideways, like the other rotate handles: about 1 degree per pixel.
   - A pointer capture that fails as a handle is grabbed is now ignored instead of raising the
     crash report.

12. Superscript and subscript digits in atom labels
   - While an atom label is being typed (e.g. "OR2" on a bond end), the Main toolbar's style
     area shows the text controls, so the x² (superscript) and x₂ (subscript) buttons are there.
   - Press x² right after typing the digits ("OR2" -> "OR²", drawn with a raised 2), or select
     digits in the label first and press it. x₂ makes them subscript ("OR₂"); pressing the same
     button again puts them back to ordinary digits. The label box keeps the keyboard, so typing
     goes on.
   - The label stores the Unicode superscript/subscript digit (² / ₂). To the chemistry it is
     the plain digit: "CH₂" counts as CH2, "R²" is an R-group like R2. Ordinary digits are drawn
     as before (lowered after a symbol, raised before one).

13. Build checks
   - The bond geometry for straight triple bonds lives in the layout engine.
   - Every dev build also runs cargo clippy (-D warnings) and cargo test, as the main
     project's Windows CI does.
